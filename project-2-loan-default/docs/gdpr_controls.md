# 🇪🇺 GDPR Compliance & Automated Decision-Making Control Matrix
**Project 2: Loan Default Risk Underwriting Engine**

---

## 1. Principle of Data Minimization (Article 5)
The underwriting engine processes only the structural data fields strictly necessary to calculate credit default probability. No auxiliary, ambient, or tertiary tracking data is logged into the inference space.

* **Authorized Features:** `CreditScore`, `Income`, `LoanAmount`, `DTIRatio`, `EmploymentLength`.
* **Prohibited Features:** Explicit markers for race, gender, religious affiliation, or exact geographic zip codes are entirely omitted from the feature store layer to prevent proxy discrimination.

## 2. Automated Decision-Making Framework (Article 22)
Because this pipeline processes loan applications automatically without mandatory human intervention, the system implements technical controls to fulfill the user's statutory rights:                                                          [Incoming Application] ──> [FastAPI Model Serving] ──> [Auto Decision]
│
┌───────────────── If Contested / Audited ───────────┘
▼
[SHAP Explainer Engine] ──> [Human Credit Officer Override]                     ### A. Right to Explanation
* Every inference response generated by the API writes a localized **SHAP (SHapley Additive exPlanations)** vector to the immutable logging database.
* If an applicant asks why their loan was denied, the application front-end queries this vector to generate a plain-language explanation of the top three driving negative features (e.g., *"Your application was declined primarily due to a Debt-to-Income ratio exceeding the 42% risk threshold"*).

### B. Right to Contest the Decision
* Any applicant rejected by the automated model retains the legal right to challenge the algorithmic output.
* Contested files trigger an internal webhook that duplicates the application context, attaches the model card version active at runtime, and flags the case for manual re-underwriting by a human risk compliance specialist.

## 3. Data Retention and Erasure Protocols (Article 17)
* **Telemetry Data:** Raw transaction logs captured in `telemetry_logs.jsonl` for drift detection are anonymized after 90 days.
* **Right to be Forgotten:** If a non-active consumer requests complete record erasure, the database service masks all identifying transactional rows. 

*Note: Aggregate statistics used to calculate historical population stability index (PSI) metrics are retained as math profiles, as they contain zero Personally Identifiable Information (PII).*
